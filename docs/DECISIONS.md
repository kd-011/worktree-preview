# worktree-preview: decisions

Why the project is the way it is, newest first. One entry per decision: the date it was made, what was decided, and why. Entries are records: when a decision stops being true, leave it and add `Superseded YYYY-MM-DD: <what replaced it>.` to its end, then add the new decision above.

The dossier for this project had no Decisions section, so these were reconstructed on 2026-11-22 from the changelog, commit messages and code comments. Each is dated by the commit or release that made it and checked against the code, and each is still true. Where no reason was written down, the entry says so.

- 2026-11-22: The agent guide and architecture doc are pinned through the existing `dossiers/` folder as links beside the self dossier, and README.md stands in for a product requirements doc. Why: dossier-scribe reads one flat folder, and the README already covers what a PRD would.
- 2026-11-03: Add `wtp up --install` (and `"install": true`), warn when a worktree declares dependencies and has no `node_modules`, and give a plain `vite` dev script `--port $PORT --strictPort`. Why: a fresh worktree has no `node_modules` and Vite ignores `PORT`, so `wtp up` failed on ordinary apps (commit 686f9ae, `src/detect.js`).
- 2026-11-03: Release is a merge. Raising the version in `package.json` on main runs `publish.yml`, which publishes to npm with provenance and makes the GitHub Release, and skips npm with a notice while the package is not on npm and no `NPM_TOKEN` secret exists. Why: trusted publishing cannot publish a package npm has never heard of, and the GitHub Release should not wait for it (`scripts/release.mjs` header, `publish.yml` header).
- 2026-11-03: Move the reference, agent and guarantee text out of the README into `docs/`, and keep the README to install, a first run, alternatives and when not to use it. Why: not recorded beyond the 0.2.0 change being about a stranger's first run (commit 686f9ae, CHANGELOG 0.2.0).
- 2026-11-02: Dependabot updates GitHub Actions only, weekly, grouped by minor and patch, with a seven-day cooldown. Updates auto-merge only when a gate script approves them and the required checks pass; majors from outside the `actions/` organisation wait for a person. Why: the repo has no npm dependencies, and `gh pr merge --auto` merges at once when no check is required, so the ruleset on main stays (`dependabot-automerge.yml` header, commit 7d5eae7).
- 2026-11-02: A weekly upkeep workflow checks the Markdown links and runs dossier-scribe, and keeps one labelled issue per problem, closing it when the next run is clean. CI also runs weekly. Why: so link rot and claims that no longer match their files show up without anyone looking, and the CI badge shows the state of main (`upkeep.yml` header, `ci.yml` comment).
- 2026-11-02: Keep a self dossier of the README's promises, pinned with dossier-scribe, with a committed lock file. Why: each promise is tied to the code behind it, so a change to that code flags the claim (commit 7d5eae7, `dossiers/worktree-preview.md`).
- 2026-11-01: Zero runtime and development dependencies, Node 22 built-ins only, Linux and macOS only. Why: not recorded beyond CONTRIBUTING.md listing them as ground rules ("if a change needs one, it is probably the wrong change"). `test/source-guards.test.js` enforces the no-dependency rule.
- 2026-11-01: Stop a preview by signalling its whole process group, and only after the registered pid still matches the recorded start time, command line and process group. Never kill by name. Why: a recycled pid must never be signalled, and grandchildren must be reaped so the port is released (`docs/guarantees.md`, `src/proc.js` header). `test/source-guards.test.js` fails on `pkill`, `killall` and any `process.kill` outside the group helper.
- 2026-11-01: Keep state under `$XDG_STATE_HOME/worktree-preview`, never in `/tmp`. Why: a systemd unit with `PrivateTmp=yes` gets its own `/tmp`, so state kept there would be invisible from a shell (`src/state.js` header, `docs/reference.md`).
- 2026-11-01: Choose the port from a hash of the worktree path and walk forward, wrapping, within 4100-4199; an explicit `--port` never moves. Why: the same worktree gets the same port each time when it is free, and a demanded port that is taken should fail rather than surprise (`docs/reference.md`, `src/ports.js`, `src/commands/up.js`).
- 2026-11-01: A preview is ready when `GET ready_path` answers below 500 on IPv4 loopback, else IPv6. Why: dev servers differ in what `localhost` binds, and a 404 still means something is answering (`src/ready.js` comment, `docs/reference.md`).
- 2026-11-01: Run the command through `/bin/sh -c "<cmd>\nexit $?"`. Why: without the trailing `exit` the shell may exec a single command and change the process identity that was recorded (`src/commands/up.js` comment).
- 2026-11-01: Serve plain HTML with a built-in static server that reads the live tree on every request and refuses anything resolving outside it. Why: a worktree with only an `index.html` should work with no config and no dependency (`src/static-server.js` header, README).
